Layout in Elegance follows SwiftUI's model. It's a conversation between parent and child, in
three steps:

1. The parent **proposes** a size to the child.
2. The child **chooses** its own size, taking the proposal into account.
3. The parent **places** the child.

A proposal can leave a dimension unspecified (asking for the child's ideal size), give zero
(asking for its minimum), or infinity (asking for its maximum). Different views respond
differently:

- `Text` takes the width it needs, up to the proposal, and wraps at word boundaries beyond that.
  It truncates with an ellipsis when it runs out of lines.
- Shapes take everything they're offered.
- `Image` keeps its own size, unless made `.resizable()`.
- Stacks divide their space among their children.
- A window proposes its size to its root view, then centers the result.

All sizes are in **logical points**; Elegance scales to the display's pixels.

## Stacks

`VStack` arranges children vertically, `HStack` horizontally, and `ZStack` on top of each other
(the first child at the back).

```cpp
VStack({.alignment = HorizontalAlignment::leading, .spacing = 4},
       Text("Elegance").font(Font::headline),
       Text("SwiftUI-style UI for C++").foreground_style(ThemeColor::secondary));

ZStack({.alignment = Alignment::bottom_trailing},
       Image({.file = "photo.jpg"}),
       Text("NEW").padding(4).background(ThemeColor::accent));
```

Stacks put `default_stack_spacing` (8 points) between children unless you set `spacing`. With the
default spacing there's no gap next to a `Spacer`. Alignment is on the cross axis: horizontal for a `VStack`, vertical for an
`HStack`, both for a `ZStack`.

### How a stack divides space

A stack offers its children space in order of flexibility: the least flexible first, so text and
images get what they need, and whatever remains goes to the flexible ones (shapes, spacers,
frames with `max_width = infinity`). Raise a child's `layout_priority` to serve it before the
others:

```cpp
HStack(Text("A long title that might need to truncate").line_limit(1),
       Text("12:30").layout_priority(1)); // the time never truncates
```

## Spacers and dividers

A `Spacer` expands along its stack's axis, pushing its siblings apart:

```cpp
HStack(Text("Settings").font(Font::headline), Spacer(), Button("Done", done));
```

`Spacer(20)` has a minimum length. A `Divider` is a thin line across its container.

## Padding

`padding` adds space around a view, 16 points by default:

```cpp
Text("A").padding();                              // 16 on every side
Text("B").padding(8);                             // 8 on every side
Text("C").padding(Edges::horizontal, 12);         // left and right
Text("D").padding(EdgeInsets{.top = 4, .bottom = 12});
Text("E").padding(EdgeInsets::symmetric(16, 8));  // horizontal, vertical
```

## Frames

`frame` with fixed dimensions sets a size, aligning the content inside it:

```cpp
Circle().fill(ThemeColor::accent).frame(40, 40);
Text("Title").frame({.width = 200, .alignment = Alignment::leading});
```

A *flexible* frame gives a range instead. The common use is to make something take all available
space:

```cpp
Button(Text("Continue").frame({.max_width = infinity}), next); // a full-width button

content.frame({.max_width = infinity, .max_height = infinity, .alignment = Alignment::top_leading});
```

The flexible form takes `min_width`, `ideal_width`, `max_width` and the same for height. The frame
takes the proposed size clamped to that range, then places the content in it.

<Aside>
To make a button wider, put the frame on its **label**, as above. A frame around the whole button
makes room around it, but the button's background stays the size of its label.
</Aside>

### Fixed size and aspect ratio

`fixed_size()` gives a view its ideal size regardless of the proposal, for example to stop a text
from wrapping. `aspect_ratio` sizes a view to a ratio within what's offered:

```cpp
Text("Never wraps").fixed_size();
Rectangle().fill(ThemeColor::surface).aspect_ratio(16.f / 9.f);
Image({.file = "cover.jpg"}).resizable().aspect_ratio(ContentMode::fill).frame(120, 120).clipped();
```

`ContentMode::fit` keeps all of the content visible; `ContentMode::fill` covers the space,
overflowing on one axis (clip it with `.clipped()` or `.clip_shape()`).

## Backgrounds and overlays

`background` and `overlay` add a view behind or in front of another, sized to it. They don't
change layout:

```cpp
Text("3")
    .padding(6)
    .background(ThemeColor::danger, Circle())
    .overlay(Circle().stroke_border(Color::white, 2));

Image("bell").overlay(Circle().fill(ThemeColor::danger).frame(8, 8), Alignment::top_trailing);
```

## Offset and stacking order

`offset` moves a view when it's drawn, without affecting the layout around it (and animates the
move during animated updates). `z_index` changes the drawing order among siblings in any stack:

```cpp
Text("Dragged").offset(drag_x, drag_y).z_index(1);
```

## Scrolling

A `ScrollView` shows its content at its ideal size along the scroll axis, clipped to the space
it's given. See [Lists and dynamic content](../lists/) for scroll views, lazy stacks and lists.
