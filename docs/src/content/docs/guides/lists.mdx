Most views are built once. Structure that changes with state goes through two views: `If`, which
switches between views, and `ForEach`, which repeats a view for each item of a collection.

## If

`If` shows one view while a condition holds, and another (or nothing) otherwise:

```cpp
If([=] { return items().empty(); },
   Text("Nothing here yet"),
   ItemList(items));

If(show_details, Details()); // a State<bool> works as the condition
```

Switching branches removes the old branch's views, including any state created inside them, and
builds the other branch. Inside a stack, the shown branch behaves as a direct child of the stack,
and an empty branch takes no space.

Changes made inside `with_animation` animate the switch: the views come and go with their
[transition](../animation/#transitions) (a fade by default).

## ForEach

`ForEach` makes one view per item of a collection. Each item has a **key** that identifies it
across changes:

```cpp
ForEach(todos, &Todo::id, [](const Todo& todo) { return TodoRow(todo); })
ForEach(todos, [](const Todo& t) { return t.id; }, TodoRow)
```

The collection is a `std::vector`, or a `State`, `Computed` or closure that produces one. When it
changes:

- items whose key and value are unchanged keep their views, and the state inside them;
- items whose value changed are rebuilt;
- removed items are removed, new ones are built.

Keys are integers, enums or strings. For collections of integers or strings, the values can be
their own keys:

```cpp
ForEach(std::vector<std::string>{"Red", "Green", "Blue"}, [](const std::string& name) { return Text(name); })
```

Inside a stack, the items are direct children of the stack, so they get its spacing and
alignment. Elsewhere they stack vertically.

<Aside type="tip">
Give items an `operator==` (`= default` is enough). Without one, `ForEach` can't tell whether an
item changed and keeps its existing view.
</Aside>

### Filtering and sorting

Pass a closure or a `Computed` that produces the visible items:

```cpp
const auto visible = computed([=] {
    auto list = todos();
    std::erase_if(list, [&](const Todo& t) { return hide_done() && t.done; });
    return list;
});
ForEach(visible, &Todo::id, TodoRow)
```

### Rebuilding a view when a value changes

A `ForEach` over zero or one item is a handy way to rebuild part of the UI whenever a value
changes: the key changes, so the old view is removed and a new one is built.

```cpp
// A new player for each file opened.
ForEach([=] { return file().empty() ? std::vector<std::string>{} : std::vector{file()}; },
        [](const std::string& path) { return VideoView(VideoPlayer(path)); })
```

## ScrollView

A `ScrollView` shows content larger than its space, clipped and scrollable with the wheel,
trackpad, scroll bars and keyboard:

```cpp
ScrollView(VStack({.alignment = HorizontalAlignment::leading}, rows...));
ScrollView({.axes = ScrollAxes::horizontal, .shows_indicators = false}, HStack(cards...));
```

The scroll view takes all the space it's offered and gives its content its ideal size along the
scroll axes. Focusing a view with Tab scrolls it into sight.

Wheel scrolling stays with the scroll view where it started until the wheel pauses for half a
second or the mouse moves. Scrolling a page down past a horizontal shelf keeps scrolling the
page; stopping over the shelf and scrolling again scrolls it sideways (a mouse wheel's vertical
notches scroll a horizontal-only view). Shift+wheel always scrolls sideways.

On a macOS trackpad, scrolling follows the fingers directly. Each swipe follows the axis it
started along, like AppKit, so a sideways swipe over a shelf scrolls the shelf, and an upward one
over the shelf scrolls the page. Past the ends the content stretches with resistance and springs
back when you let go. Let go while moving and it glides on at your fingers' speed, slowing down
like UIScrollView, and bounces off the ends. Touching the trackpad again stops it.

### Scrolling from code

Create a `ScrollPosition`, pass it in the options, and call it from event handlers:

```cpp
const auto position = ScrollPosition();

ScrollView({.position = position}, LazyVStack(ForEach(messages, &Message::id, MessageRow)));
Button("Newest", [=] { position.scroll_to_end(); });
Button("Top", [=] { position.scroll_to_top(); });
Button("Pinned", [=] { position.scroll_to(pinned_id()); }); // a ForEach key
```

### Chat logs

With `.sticks_to_end = true` a scroll view starts at the end, and while it's scrolled to the end
it stays there as its content grows: new messages, or images loading in. It snaps rather than
animating. Scroll back even a little and it stays where it is, so reading history isn't
interrupted; scroll to the end again to follow it.

Lazy stacks also keep what's on screen in place when rows above it change size (estimates
replaced by real heights, or items inserted above), so loading older messages doesn't jump.

```cpp
ScrollView({.sticks_to_end = true}, LazyVStack(ForEach(messages, &Message::id, MessageRow)));
```

## Lazy stacks

A `VStack` builds all of its children. For long collections, use `LazyVStack` or `LazyHStack`
inside a scroll view: only the items in or near the visible area are built, and the size of the
rest is estimated from the items seen so far. Items scrolled far away are destroyed, with their
state.

```cpp
ScrollView(LazyVStack({.spacing = 4}, ForEach(messages, &Message::id, MessageRow)));
```

The argument must be a `ForEach`. Lazy stacks handle tens of thousands of items.

## List

`List` is a lazy, scrolling list of rows with separators, row padding and a hover highlight, on a
rounded surface:

```cpp
List(ForEach(contacts, &Contact::id, [](const Contact& c) { return ContactRow(c); }));

const auto position = ScrollPosition();
List({.position = position}, ForEach(contacts, &Contact::id, ContactRow));
```

See the [todos example](../../examples/#todos) for a complete list with adding, removing and
toggling items.
