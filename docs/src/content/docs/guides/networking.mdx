Elegance makes HTTP(S) requests with the system's own networking: WinHTTP on Windows, which uses
the system's certificates and proxy settings and supports HTTP/2 and compression. Requests run on
background threads; results arrive on the UI thread, where you can write state.

## A request with a callback

```cpp
http::fetch({.url = "https://api.example.com/items"}, [=](const http::Result& result) {
    if (!result) {
        error = result.error();          // no response: network, TLS, timeout
    } else if (!result->ok()) {
        error = std::format("HTTP {}", result->status);
    } else {
        items = parse_items(result->text());
    }
});
```

A `Request` has a `url`, a `method` (GET by default), `headers`, a `body` and a `timeout`
(30 seconds):

```cpp
http::fetch({.url = "https://api.example.com/items",
             .method = "POST",
             .headers = {{"Content-Type", "application/json"}, {"Authorization", "Bearer " + token}},
             .body = R"({"title": "New item"})"},
            on_done);
```

The `Result` is a `std::expected<Response, std::string>`: a response, or why there isn't one. An
HTTP error status is still a response, so check `ok()` (a 2xx status). A `Response` has the
`status`, `headers` (`header("content-type")` finds one by name), and the `body` as bytes, with
`text()` for a string.

`fetch` returns an `http::Task`; `cancel()` stops the request, and its callback won't run.
`fetch` can be called from any thread.

## A request as state

`http::Fetch` starts a request when it's made, and views reading it update when it finishes:

```cpp
const http::Fetch profile("https://api.example.com/me");

If([=] { return profile.is_loading(); },
   ProgressView(),
   Text([=] { return profile.ok() ? profile.response().text() : profile.error(); }));

Button("Refresh", [=] { profile.reload(); });
```

`is_loading()`, `has_response()`, `ok()`, `response()` and `error()` are reactive. `reload()` starts
it again, keeping the old result until the new one arrives. Copies share the request, and it's
cancelled when the last copy goes.

Elegance doesn't include a JSON library; use the one you like (nlohmann/json, Glaze, simdjson) on
`response().text()`.

## WebSockets

`http::WebSocket::connect` opens a WebSocket on a background thread (WinHTTP on Windows). Its events
run on the UI thread:

```cpp
const auto socket = http::WebSocket::connect(
    {.url = "wss://echo.example.com", .headers = {{"Origin", "https://example.com"}}},
    {.on_open = [=] { status = "Connected"; },
     .on_message = [=](const std::string& text) { log.update([&](auto& l) { l.push_back(text); }); },
     .on_close = [=](int code, const std::string& reason) { status = reason; }});

socket.send(R"({"type": "hello"})");
```

`on_message` gets whole messages, however many frames they came in. `on_close` runs once, last:
with the server's close code and reason, or with 1006 and why in words when the connection failed
or dropped. `send()` queues while connecting and works from any thread, so a heartbeat can run on
its own thread. `close()` ends it without running `on_close`; so does dropping the last copy.
