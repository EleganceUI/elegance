Elegance doesn't have its own HTTP or WebSocket API. Use an established library that you trust
and keep up to date, such as [libcurl](https://curl.se/libcurl/),
[Boost.Beast](https://www.boost.org/libs/beast) or [cpp-httplib](https://github.com/yhirose/cpp-httplib).
Elegance gives you two things to connect it to your views:

- `post_to_ui_thread(task)` runs `task` on the UI thread, where it can write state.
- `AsyncImage(url)` downloads and shows images. See
  [Images](../images/#images-from-the-web).

## Requests on a background thread

Run requests off the UI thread, so the window keeps responding. When a result arrives, hand it
back with `post_to_ui_thread`. This example uses cpp-httplib:

```cpp
#include <httplib.h>

using Body = std::expected<std::string, std::string>; // the body, or why there isn't one

// `done` runs on the UI thread.
void get(std::string server, std::string path, std::function<void(const Body&)> done) {
    std::thread([=] {
        httplib::Client client(server);
        client.set_follow_location(true);
        const auto response = client.Get(path);
        Body body;
        if (!response) {
            body = std::unexpected(httplib::to_string(response.error())); // network, TLS, timeout
        } else if (response->status != 200) {
            body = std::unexpected(std::format("HTTP {}", response->status));
        } else {
            body = response->body;
        }
        post_to_ui_thread([done, body = std::move(body)] { done(body); });
    }).detach();
}
```

Inside `done`, write state as usual. Views that read it update:

```cpp
const State<bool> loading(true);
const State<std::string> quote;

get("https://api.github.com", "/zen", [=](const Body& body) {
    quote = body ? *body : body.error();
    loading = false;
});

If([=] { return loading(); }, Progress(), Text([=] { return quote(); }));
```

`State` is a handle. A callback that holds a copy can still write to it after the view that
showed it has gone, and nothing shows the change. If the work is costly, or must not run once a
view has gone, give the callback a flag to check, or use your library's cancellation.

## WebSockets

The same rules apply to WebSockets: run the connection on its own thread, or the library's event
loop, and post each message to the UI thread. Boost.Beast and libcurl both support WebSockets.

## JSON

Elegance doesn't include a JSON library either. Use the one you like (nlohmann/json, Glaze,
simdjson) on the body before you post it to the UI thread, so parsing doesn't stall the window.
