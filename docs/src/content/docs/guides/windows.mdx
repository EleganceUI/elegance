## The app and its windows

`App` owns the application: its windows, the event loop and the render thread. Create one, add
windows, and call `run()`, which returns when the last window closes or `quit()` is called:

```cpp
int main() {
    App app;
    app.window({.title = "Editor", .width = 1200, .height = 800}, EditorView);
    app.window({.title = "Palette", .width = 300, .height = 500}, [] { return Palette(); });
    return app.run();
}
```

The content function builds the window's root view. It runs once, on the UI thread, when the
window opens.

### Window options

| Option | Default | Meaning |
| --- | --- | --- |
| `title` | `"Elegance"` | The title bar and taskbar text |
| `width`, `height` | 1280 × 720 | The initial size, in points |
| `resizable` | `true` | Whether the user can resize it |
| `min_size` | none | The smallest size the user can resize to |
| `background` | the theme's `background` | Shown where no view draws |
| `title_bar` | `TitleBar::system` | `TitleBar::integrated` for content under the system's controls, `TitleBar::hidden` to draw your own |
| `system_controls_position` | macOS's | Integrated title bars: where the system's window controls go (macOS) |
| `transparent` | `false` | The desktop shows through where nothing opaque is drawn |
| `opacity` | 1 | The whole window's opacity |

Windows follow the display's scale (DPI) and move between monitors with different scales. Resizing
is live: content lays out continuously while the edge is dragged.

## Custom title bars

With `TitleBar::hidden` the content fills the whole window. Draw your own title bar, make it drag
the window with `.window_drag_area()`, and add `WindowControls()`:

```cpp
app.window({.title = "Notes", .title_bar = TitleBar::hidden}, [] {
    return VStack({.spacing = 0},
                  HStack(Text("Notes"), Spacer(), WindowControls())
                      .frame({.height = 36})
                      .window_drag_area(),
                  Content());
});
```

Dragging the area moves the window and double-clicking maximizes it, like a system title bar.
Controls inside it still work. The window's edges still resize it.

`WindowControls` draws minimize, maximize and close buttons in the platform's style, or in the
style you choose. It draws them only in `TitleBar::hidden` windows: wherever the system has its own
controls, it's empty, so a layout can include it on every platform.

```cpp
WindowControls({.style = WindowControlsStyle::traffic_lights, .maximize = false})
```

### Integrated title bars

`TitleBar::integrated` keeps the system's own window controls and lets the content fill the window
under them. On macOS that's the native traffic lights over a transparent title bar, and
`system_controls_position` moves them (the close button's top-left corner, in points). Platforms
without controls that sit over the content keep their system title bar, so an app never shows
imitation buttons where real ones exist.

`system_controls_frame()` is where the controls are, in the window's points, and is empty where
there are none (in fullscreen, too). Keep content clear of it, reactively:

```cpp
app.window({.title = "Music", .title_bar = TitleBar::integrated, .system_controls_position = Point{20, 27}},
           [] {
               const auto window = Environment<WindowKey>();
               return VStack(EmptyView().frame([=] { return Size{0, window().system_controls_frame().max_y()}; }),
                             SearchField())
                   .window_drag_area();
           });
```

For other differences between platforms, `current_platform()` (`elg/platform.h`) is
`Platform::windows`, `macos` or `linux`, and is `constexpr`.

### The current window

`Environment<WindowKey>()` gives the window a view is in. Its readers are reactive, which helps
title bars dim when the window isn't active:

```cpp
const auto window = Environment<WindowKey>();
TitleBar()
    .opacity([=] { return window().is_active() ? 1.f : 0.6f; });
Button("Close", [=] { window().close(); });
Text([=] { return window().is_maximized() ? "Maximized" : "Normal"; });
```

`WindowHandle` has `close()`, `minimize()`, `toggle_maximized()`, `is_maximized()` and
`is_active()`.

## Transparent windows

With `transparent = true`, the desktop shows through wherever the window's content isn't opaque.
Combined with a hidden title bar, that gives rounded or shaped windows and translucent panels:

```cpp
app.window({.title = "Widget", .width = 340, .height = 190,
            .title_bar = TitleBar::hidden, .transparent = true},
           [] { return Widget().background(ThemeColor::surface, RoundedRectangle(16)); });
```

<Aside>
Transparency needs a compositing window system; where it isn't available the window stays opaque.
On Windows, every window is presented through DirectComposition, which also keeps live resizing
free of stretching.
</Aside>
