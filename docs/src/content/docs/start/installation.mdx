Elegance is built from source with CMake. Its dependencies come from
[vcpkg](https://vcpkg.io) in manifest mode, so they're downloaded and built for you on the first
configure.

## Requirements

- **Windows 10 or 11**, x64.
- **Visual Studio 2022 or later** with the C++ workload (MSVC with C++23 support).
- **CMake 4.3** or later, and **git**. Ninja and vcpkg are optional: the configure fetches Ninja
  when it isn't installed, and uses the vcpkg at `VCPKG_ROOT`, or clones its own into
  `%LOCALAPPDATA%\elegance\vcpkg` (`~/.cache/elegance/vcpkg` on macOS and Linux).
- A GPU with **Direct3D 12** (or Direct3D 11 or Vulkan) drivers. Elegance draws with WebGPU,
  through Google's Dawn, which vcpkg builds from source the first time: allow about half an hour
  and 20 GB of free disk space for that build.

## Build the repository

<Steps>

1. Configure with a preset. Run this from a **Developer Command Prompt** (or in CLion or Visual
   Studio, which set up the compiler for you):

   ```sh
   cmake --preset windows-debug
   ```

   The first configure builds the dependencies (SDL3, FreeType, HarfBuzz, miniaudio and a few
   more), which takes a while. Later configures reuse them.

2. Build:

   ```sh
   cmake --build build/windows-debug
   ```

3. Run the sandbox, which shows most features in one window:

   ```sh
   build\windows-debug\bin\sandbox.exe
   ```

   The examples are in their own repository,
   [elegance-examples](https://github.com/EleganceUI/elegance-examples).

</Steps>

The presets are `windows-debug` and `windows-release` (RelWithDebInfo), plus two static ones (see
[Linking statically](#linking-statically)): `windows-release-static` links Elegance into each app,
and `windows-release-fully-static` links everything, so each app is a single executable.
Everything lands in `build/<preset>/bin`.

### macOS (Apple Silicon)

Use **Xcode 26 or later**, selected with `xcode-select`. Xcode 16's libc++ does not expose
`std::jthread` and `std::stop_token`, even in C++23 mode.

vcpkg needs `pkg-config` to build the dependencies (`brew install pkg-config`). Then:

```sh
cmake --preset macos-debug
cmake --build build/macos-debug
```

The macOS presets set `CMAKE_OSX_DEPLOYMENT_TARGET=13.3` and use the overlay triplet in
`cmake/triplets/arm64-osx.cmake` to build vcpkg dependencies for the same deployment target.
The compiler/SDK version and deployment target are independent: a new Xcode can still target
an older macOS.

If an existing build warns that dependency objects were built for a newer macOS version than
13.3, rerun `cmake --preset macos-debug` before building. The updated triplet invalidates the
old vcpkg binaries and rebuilds dependencies; the first configure can take as long as a fresh
install. `cmake --fresh` alone does not rebuild dependencies with the wrong deployment target.
If you change the deployment target, update both the preset and overlay triplet together.

## Build options

| Option | Default | What it does |
| --- | --- | --- |
| `ELG_BUILD_SHARED` | `ON` | Build Elegance as a DLL. `OFF` links it statically into each app. Hot reload needs `ON`. |
| `ELG_BUILD_SANDBOX` | top level | The sandbox and, with a shared build, the hot reload preview app. |
| `ELG_BUILD_TESTS` | top level | Unit tests (needs the vcpkg `tests` feature). |
| `ELG_ICONS` | `ON` | Embed the Phosphor icon set (regular, bold, fill; about 1.4 MB). |
| `ELG_ICONS_EXTRA_WEIGHTS` | `ON` | Also embed Phosphor's thin, light and duotone styles (about 1.6 MB). |
| `ELG_ACCESSIBILITY` | `ON` | Screen reader support through AccessKit (downloads its prebuilt library). |

## Use it in your project

The quickest start is to copy an example from
[elegance-examples](https://github.com/EleganceUI/elegance-examples), such as `hello-cpp`: each
one is a complete project, which downloads Elegance when there's no checkout beside it. Or set it
up yourself:

Add Elegance as a subdirectory, for example as a git submodule, and link `Elegance::Elegance`:

```cmake title="CMakeLists.txt"
cmake_minimum_required(VERSION 4.3)
project(MyApp LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 23)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

add_subdirectory(external/elegance)

add_executable(my_app main.cpp)
target_link_libraries(my_app PRIVATE Elegance::Elegance)

# Keep the app next to elegance.dll so Windows finds it.
set_target_properties(my_app PROPERTIES RUNTIME_OUTPUT_DIRECTORY ${CMAKE_BINARY_DIR}/bin)
set_target_properties(elegance PROPERTIES RUNTIME_OUTPUT_DIRECTORY ${CMAKE_BINARY_DIR}/bin)

if (MSVC)
    target_compile_options(my_app PRIVATE /utf-8)
endif ()
```

### Linking statically

Set `ELG_BUILD_SHARED` to `OFF` before adding Elegance, and the app ships without
`elegance.dll`:

```cmake title="CMakeLists.txt"
set(ELG_BUILD_SHARED OFF CACHE BOOL "" FORCE)
# Where Elegance copies the DirectX shader compiler (dxcompiler.dll, dxil.dll), which Direct3D 12
# loads at run time. Without it, Direct3D 12 compiles shaders with the much slower FXC.
set(CMAKE_RUNTIME_OUTPUT_DIRECTORY ${CMAKE_BINARY_DIR}/bin)
add_subdirectory(external/elegance)
```

Its dependencies (SDL, Dawn, FreeType, HarfBuzz) stay DLLs with the `x64-windows` triplet, and
vcpkg copies them next to the app. Hot reload needs the shared library: one Elegance for the host
and its reloadable modules, so `elegance_hot_reload()` stops with an error in a static build.

#### One executable

With vcpkg's `x64-windows-static` triplet (the `windows-release-fully-static` preset), the
dependencies and the C runtime are static too (`/MT`), and an app needs nothing beside it but
Windows. Elegance notices the triplet: it switches the build to the static runtime and builds
itself static (a shared Elegance with its own runtime couldn't share `std` types with the app).

```sh
cmake --preset windows-release-fully-static   # the first time, vcpkg builds Dawn: allow ~30 minutes
cmake --build build/windows-release-fully-static
```

The preset builds Release without debug info: with everything linked in, each app's PDB would
carry all of Dawn's (about 700 MB). An app is about 20 MB. `dxcompiler.dll` and `dxil.dll` (the
DirectX shader compiler, which Microsoft ships only as DLLs) are optional beside it: without them,
Direct3D 12 compiles shaders with the older FXC, so the first frames take longer.

vcpkg only reads the manifest of the top-level project, so your project needs Elegance's
dependencies in its own `vcpkg.json`:

```json title="vcpkg.json"
{
  "name": "my-app",
  "version": "0.1.0",
  "dependencies": [
    "freetype",
    "harfbuzz",
    "miniaudio",
    { "name": "msdfgen", "default-features": false },
    { "name": "stb", "platform": "!windows" },
    "sdl3",
    "dawn"
  ]
}
```

Configure with vcpkg's toolchain file, as the presets do:

```sh
cmake -B build -G Ninja -DCMAKE_TOOLCHAIN_FILE=%VCPKG_ROOT%/scripts/buildsystems/vcpkg.cmake
```

<Aside type="tip">
Compile with `/utf-8` on MSVC. Elegance's strings are UTF-8, and without the flag string literals
with non-ASCII characters (`"−"`, `"…"`) are mangled by the source code page.
</Aside>

## Check that it works

```cpp title="main.cpp"
#include <elg/elegance.h>

int main() {
    elg::App app;
    app.window({.title = "It works"}, [] { return elg::Text("Hello from Elegance"); });
    return app.run();
}
```

If the window doesn't open, run the app from a terminal: errors are printed to stderr, and the
log says which GPU was picked.
